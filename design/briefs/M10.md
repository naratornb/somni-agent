# M10 — UI Redesign: Nocturnal Mission Control — Execution Brief

## Context

The PO produced a Stitch redesign in [design/stitch_somni_ai_orchestrator/](../stitch_somni_ai_orchestrator/): four screen mocks (`pipeline_dashboard`, `workflows_editor`, `runs_reports`, `drafting_interface` — each `code.html` + `screen.png`) and the design system in [somni_nocturnal_mission_control/DESIGN.md](../stitch_somni_ai_orchestrator/somni_nocturnal_mission_control/DESIGN.md). The mocks reflect the post-M9 app (Draft view, Backlog/Promote, Drain queue, Keep Running). The current renderer is one hand-written `src/renderer/src/assets/main.css` with zero styling dependencies. This milestone reskins the whole app before M11/M12 so their UI work is built once, on the new skin. Build-plan entry: architecture.md §9, M10.

## Goal & success criteria

- All seven nav views (Workflows, Draft, Pipeline, Runs, Roles, Settings, Playground) render in the new design system; the four mocked screens visibly match their `screen.png` (directional, not pixel-court).
- Real flows still work end-to-end in the reskinned UI: tick → Run, Drain queue, park/promote Backlog, Draft interview → Apply, editor chat, run reports, worktree cleanup.
- `npm test` green; `npm run build` succeeds; built renderer output contains no CDN URLs (`grep -rE "googleapis|cdn.tailwindcss" out/` finds nothing).
- Dark-only. Legacy `main.css` rules fully removed once views are converted.

## Staffing

Full tier per design/team.md: ux-designer (first), fullstack-engineer, tester. TD verifies and merges.

## Scope

### Designer (runs first)

- Spec the four unmocked surfaces from DESIGN.md's tokens and component rules — no new tokens, no new colors:
  - **Roles view** (list + role editor incl. runner/model/effort selects and preamble textarea).
  - **Settings view** (global settings form, runner binaries, Nightly row with Armed/Disarmed chip).
  - **Playground** (prompt box + mono output on true-black per DESIGN.md live-log rule).
  - **Editor chat panel** (`DraftChatPanel` — the fixed 340px right panel; align it with the mocked full-page Draft chat so the two chats read as one component per DESIGN.md's "unified chat experience").
- Define the interview **question-chip card** and **Propose Now** styling the drafting mock omits, from DESIGN.md's "Interview Flow" component (one card, clickable pill-chips, recommended option highlighted).
- Deliverable: `design/briefs/M10-ui.md` — component structure + token usage per surface, same format as M8-ui/M9-ui.

### Engineer (after the designer's spec is accepted)

In dependency order:

1. **Tailwind v4 wiring.** `npm i -D tailwindcss @tailwindcss/vite`; add the plugin to the renderer section of `electron.vite.config.ts`; replace `src/renderer/src/assets/main.css` content with `@import "tailwindcss";` plus an `@theme` block declaring every DESIGN.md token (colors incl. the `status-*` scale, fonts, radii, `--spacing-sidebar-width: 240px`, `--spacing-editor-panel-width: 340px`). Token names must match the mocks' inline `tailwind.config` so mock markup ports verbatim. Dark values are the only values — no `dark:` variants.
2. **Bundled assets.** Vendor woff2 into `src/renderer/src/assets/fonts/`: Inter (400/500/600), JetBrains Mono (400/500), Material Symbols Outlined (subset to the glyphs the app uses if practical; the full variable font is acceptable if subsetting fights back). `@font-face` in the CSS entry. Zero runtime network fetches.
3. **Shell.** Port the shared shell from any mock into `App.tsx`: 240px fixed sidebar (wordmark + Material Symbols nav icons), repo bar, main content offset. Keep the existing `useState<View>` routing untouched.
4. **Mocked screens.** Port markup from each `code.html` into the existing components, preserving all shipped behavior (directional fidelity — functionality wins over the mock): `PipelineView.tsx` ← pipeline_dashboard, `WorkflowsView.tsx` ← workflows_editor (incl. Backlog section, Brief `<details>`, task cards), `RunsView.tsx` ← runs_reports, `DraftView.tsx` ← drafting_interface.
5. **Unmocked surfaces** from the accepted `M10-ui.md`: `RolesView.tsx`, `SettingsView.tsx`, `Playground.tsx`, `DraftChatPanel.tsx` + `chatShared.tsx` (QuestionCard/ProposalPreview per the designer's interview-card spec).
6. **Legacy removal.** Delete remaining old `main.css` rules and stray inline styles; the CSS entry ends as tokens + @font-face + the few rules utilities can't express (scrollbars, ANSI log styling).

Constraints: main-process code is untouched; no new IPC; no router or component library beyond Tailwind itself.

### Tester (after engineering)

- Walk all seven views against the four `screen.png`s and `M10-ui.md`; report visual gaps per view.
- Functional regression in the running app: create/edit/delete workflow and roles; tick → Run; Drain queue; park → promote Backlog; Draft interview through Apply (question chips clickable, Propose Now visible); editor chat; run report render; Settings edits persist; Playground prompt.
- `npm test` (store/executor/chat/report/runners/stream suites) green; `npm run build`; grep built output for CDN URLs; launch the packaged app with networking unavailable and confirm fonts/icons render.

## Out of scope

Light mode or theme switching; M11 (Refine with AI, `listModels()`, PO/Engineer view modes); M12 (voice); any behavior change to executor/store/chat/report; redesigning flows the mocks don't change (no new features ride along).

## Verification plan

TD reviews the designer spec before engineering starts; after tester sign-off, TD re-runs `npm test` + `npm run dev`, spot-checks each view against its `screen.png`, and merges the single `m10-redesign` PR (this brief, the committed stitch folder, and the implementation ride together).
