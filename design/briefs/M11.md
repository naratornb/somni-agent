# M11 — Refine, model lists, view modes — Execution Brief

## Context

Phase-2 close-out before voice (M12). Three features from [architecture.md §9](../architecture.md): one-shot **Refine with AI** on task prompts and role preambles (workflow-*structure* refinement routes through the editor chat as a canned message), **`listModels()`** on the Runner adapters (CLI query → curated fallback → free-text combo), and **PO/Engineer view modes** (presentation-only sidebar switch). Domain rules in [CONTEXT.md](../../CONTEXT.md) bind: Refine never interviews and follows the Apply rule (inert until deliberately accepted; nothing touches disk before then); PO hat = brief, queue, review outcomes; Engineer hat = full editing; modes are presentation only. Design resolved with a TD-reviewed plan at kickoff; decisions below are frozen.

## Goal & success criteria

- `npm test`, `npm run lint`, `npm run build` pass.
- In the running app: Refine a task prompt → inert result card → Apply → textarea updated, disk unchanged until Save; same for a role preamble; "Refine structure" in the editor chat yields an ordinary Proposal handled by the existing Apply path; the model fields in Settings and the role editor suggest models but still accept free text; the agy list mirrors `agy models` when the CLI answers and falls back to a pinned list when it doesn't; the sidebar toggle flips PO ↔ Engineer, hides/shows the right views, falls back to Workflows when the current view disappears, and survives restart.

## Staffing

UI-involved tier: **Engineer + Tester + Designer**. Designer and Engineer start in parallel (Engineer on main-process + preload scope); renderer work follows the accepted design (`M11-ui.md`).

## Scope

### Decisions (frozen)

1. **Refine = one-shot, main-process.** Export `runnerText` in place from `src/main/report.ts:153` (second consumer noted in its comment). New invoke `field:refine(repo, kind: 'task' | 'role', text)` → `{ok, text?, error?}` in `wireRepoIpc`: two fixed kind-specific prompt consts (rewrite this Task prompt / Role preamble into a sharper, self-contained version for an unattended coding agent; reply with ONLY the rewritten text — no commentary, no code fences), run read-only with cwd = repo and the **global-settings profile** (as `chat:send` does — role overrides are not consulted). Refuse empty text. No main-side in-flight guard — each invoke is stateless; the renderer disables its own button while pending.
2. **Refine Apply rule in the renderer.** One shared `RefineControl({repo, kind, text, onApply})` in `chatShared.tsx`: ghost "Refine" button (existing `auto_awesome` glyph — **no new glyphs anywhere in M11**; the Material subset would need regenerating), result shown inert in the CARD idiom with Apply/Dismiss (ProposalPreview action row); Apply swaps into the **editing buffer only** (`patchTask(i, {prompt})` / `setEditing({…, preamble})`); disk is written only by the editor's own Save.
3. **Structure refine = canned message, zero new IPC.** `REFINE_STRUCTURE` const in `chat.ts` following the `PROPOSE_NOW` pattern (duplicated in preload as data prop `refineStructure`; sent as an ordinary `chat:send` from a button beside Propose Now in `DraftChatPanel.tsx` only — DraftView untouched, a `_draft` has no structure). The message asks to reread the workflow's definition and propose a refined version now (tighter task boundaries, ordering, prompts, role fit; keep the intent) — it must **not** re-teach the proposal format; the preamble's existing `somni-workflow` instruction covers it, and the reply lands as an ordinary Proposal through the existing `proposal:apply`.
4. **Preamble names the workflow file.** `draftPreamble(roleSlugs, brief?, slug?)` appends, for editor chats only: "This chat edits the existing workflow stored at `.somni/workflows/<slug>.json`; read it for the current structure." `turnArgs`/`sendChat` pass `slug === DRAFT_KEY ? undefined : slug`. Without this a fresh-chat structure refine is structure-blind (turn 1 carries only the Brief today).
5. **`listModels` lives on the adapters.** `Runner` gains `listModels: (binary: string) => Promise<string[]>` (binary as a param — `getRunner` returns a spread copy, and tests point at fixture scripts directly). claude: resolve `['fable', 'opus', 'sonnet']` immediately (its CLI has no models subcommand; the list is exactly what `claude --help` names). antigravity: `promisify(execFile)(binary, ['models'], {timeout: 10_000})`; stdout is `id\tLabel` lines with noise on stderr — take the field before the first tab, drop non-tab lines; any error or empty parse → a short pinned fallback of current agy ids with a `ponytail:` comment (fallback only; the live query is the source).
6. **`models:list(runnerName?)` invoke** in `wireRepoIpc`: `undefined → readSettings().runner → 'claude'` resolved **in main** (the role editor's inherit case must not resolve profiles renderer-side); memoized for the app session in a Map keyed `` `${name}:${binary}` ``. Ceiling (`ponytail:` comment): repo-level `config.json` overrides aren't consulted — no repo param.
7. **Combo boxes are native.** `<input list=…>` + `<datalist>` on the model fields in `SettingsView` (fetch keyed on the unsaved form value `s.runner`) and `RolesView` (keyed on `editing?.runner`, passed through as-is). Distinct datalist ids per view. Rewrite the standing `ponytail:` comment at `SettingsView.tsx:122-123` — datalist = live-queried suggestions, still free text, nothing ships stale.
8. **View mode is a settings field.** `ViewMode = 'po' | 'engineer'`; `viewMode?: ViewMode` on `Settings`; `viewMode: 'engineer'` in `SETTINGS_DEFAULTS` (upgrade changes nothing). Persisted via existing `settings:get`/`settings:set`; preload `setSettings` widens to `Partial<Settings>` so the toggle sends `{viewMode}` alone (`patchSettings` already shallow-merges). No new IPC, no localStorage.
9. **PO shows Draft, Workflows, Pipeline, Runs; Engineer shows all seven.** Nav filters the existing `VIEWS` registry, order kept (ticks + Backlog live in WorkflowsView, so it stays in PO). Switch = text segmented toggle ("PO | Engineer") at the sidebar-bottom slot; switching to PO while on a hidden view → `setView('Workflows')`. Presentation only — nothing else changes.
