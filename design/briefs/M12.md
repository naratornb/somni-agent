# M12 — Voice input — Execution Brief

## Context

Phase-2 close-out, per [architecture.md §9](../architecture.md) and [ADR 0001](../../docs/adr/0001-in-app-whisper-voice-input.md): an in-app mic button on every AI-adjacent text field, backed by locally run whisper.cpp `base.en`; the *model* downloads on first use (never bundled); English-only accepted; macOS dictation (fn-fn) remains the working fallback in every field — zero code. Voice serves the PO hat's least-effort briefing (CONTEXT.md: a Brief is "written (or dictated)"). Design resolved with a TD-reviewed plan at kickoff; decisions below are frozen.

Facts pinned against this machine at kickoff: Homebrew `whisper-cpp` 1.9.2 installs **`whisper-cli`** (now at `/opt/homebrew/bin/whisper-cli`; no official prebuilt macOS artifact exists otherwise). Flags verified live: `-m FNAME` model, `-f FNAME` input (16-bit 16 kHz mono WAV), `-np` no prints, `-nt` no timestamps, language defaults to `en`. Model: `https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-base.en.bin` (~142 MiB). Electron 39 (Chromium ~142). This branch (`m12`) stacks on the unmerged `m11` (PR #12).

## Goal & success criteria

- `npm test`, `npm run lint`, `npm run build` pass.
- In the running app with no model present: the mic button on the Draft field offers a model download, streams it with visible progress into `userData/models/ggml-base.en.bin`, then records; with the model present: click → record → click → transcribed text appends to the field. All four fields carry the button; with `whisperBinary` unset and `whisper-cli` missing from PATH the button renders disabled with the install hint; Settings round-trips `whisperBinary`.
- End-to-end transcription proof without a human mic: a `say`-synthesized 16 kHz WAV fed through the transcribe path returns the spoken words.

## Scope

### Decisions (frozen)

1. **Binary = brew-installed `whisper-cli`, never app-distributed.** New `whisperBinary?: string` setting (empty = PATH lookup of `whisper-cli`) — byte-for-byte the `claudeBinary` pattern (`store.ts`, preload duplicate, one new SettingsView `FieldRow`). Missing binary ⇒ mic button disabled with title "Install whisper.cpp (brew install whisper-cpp) or set the path in Settings".
2. **Capture is renderer-side and minimal**: `getUserMedia({audio: true})` → `new AudioContext({sampleRate: 16000})` (Chromium resamples the mic to the context rate) → `ScriptProcessorNode(4096, 1, 1)` accumulating `Float32Array` chunks → on stop, concatenate and send ONE `Float32Array` over invoke. `ponytail:` comment names AudioWorklet as the upgrade path (a worklet asset under electron-vite is plumbing for zero user-visible gain). No MediaRecorder, no renderer-side Int16 conversion — the float→Int16 clamp/scale lives in main's WAV encoder where it is pure and unit-testable. Mic permission: the getUserMedia TCC prompt is the whole flow; a rejection surfaces as the button's error state ("mic access denied — System Settings"). No `askForMediaAccess` in main.
3. **`src/main/voice.ts`** — one small boring module:
   - `wavFromPcm(samples: Float32Array, sampleRate)` — pure 44-byte-header 16-bit mono WAV encoder including the clamp/scale.
   - `voice:status` invoke → `{binary: boolean, model: boolean}`. Binary probe = one `execFile(bin, ['--help'])`, **cached for the app session** (the `modelCache` idiom; a settings change may serve a stale probe until restart — accepted). Model = `existsSync(userData/models/ggml-base.en.bin)`.
   - `voice:downloadModel` invoke — streams the HF URL with global `fetch` to `<path>.tmp`, renames on success (the atomic pattern, done manually for a stream); pushes `voice:modelProgress {received, total}` via the standard webContents.send path. Download-before-record is deliberate: recording first and downloading after would waste the user's speech.
   - `voice:transcribe(samples)` — fixed temp path `join(os.tmpdir(), 'somni-voice.wav')` (safe: see the guard), `promisify(execFile)(bin, ['-m', model, '-f', wav, '-np', '-nt'], {timeout: 60_000})`, transcript = stdout trimmed, temp `rmSync(force)` in `finally`, `{ok, text?, error?}`. Errors if the model is absent (belt-and-braces; the button never lets this happen). **Module-level boolean in-flight guard** — a concurrent call returns `{ok:false, error:'transcription already running'}`; it doubles as mic exclusivity across fields.
4. **`MicButton({onText, disabled?})` in `chatShared.tsx`** — the shared component + capture logic. States: `no-binary (disabled+hint) → no-model (click starts download) → downloading (pct from onVoiceProgress) → idle → recording (click stops) → transcribing → idle`, transient error via the `ERROR_BANNER` idiom. `onText(text)` **appends** to the field's controlled value (space-separated) — no cursor-position insertion (macOS dictation already does that better, and it stays available). Four call sites: DraftView chat textarea (~:161) and DraftChatPanel textarea (~:160) — in the input row near Send; WorkflowsView task-prompt and RolesView preamble — beside the existing RefineControl button. Styling: existing atoms only (`BTN_GHOST_SM`/`ICON_BTN`, chips, `ERROR_BANNER`); recording state may reuse the status-chip color vocabulary. **The `mic` Material glyph is the one allowed subset addition** — regenerate the font subset per the `ponytail:` procedure in `assets/main.css` and keep every existing glyph.
5. **Packaging**: add `com.apple.security.device.audio-input` to `build/entitlements.mac.plist` (one key, inert in dev).
6. **Preload**: duplicate types; methods `voiceStatus`, `downloadModel`, `transcribe`; push hook `onVoiceProgress` via the `on()` helper. Bridge additions are methods-only — the SSR stub needs no new seeding.

### Engineer

Dependency order (match existing style, no new npm deps):

1. `src/main/store.ts` — `Settings.whisperBinary`.
2. `src/main/voice.ts` — encoder + the three handlers' logic (export a `wireVoiceIpc()` or wire from `repoIpc.ts`, whichever reads smaller; keep every voice decision in voice.ts).
3. `src/preload/index.ts` — types + methods + `onVoiceProgress`.
4. `src/renderer/src/chatShared.tsx` — `MicButton` + capture; four call sites (`DraftView`, `DraftChatPanel`, `WorkflowsView`, `RolesView`); `SettingsView` FieldRow for `whisperBinary`.
5. `build/entitlements.mac.plist` — the audio-input key.
6. Material subset regeneration for `mic` (procedure in `main.css`; verify existing glyphs still render).

Per Karpathy guideline 4, ship minimal vitest coverage with the logic (Tester extends): WAV header/clamp, transcribe happy path with a fake binary.

### Tester

Ride the existing harnesses; concrete failing output on miss:

- `src/main/voice.test.ts` (new): `wavFromPcm` byte-exact header fields (RIFF sizes, fmt 16/1/16000, data length) + Int16 clamping at ±1.0 overrange; transcribe via a fake `whisper-cli` on PATH (chat.test.ts pattern) — argv log asserts `-m <model> -f <wav> -np -nt`, the temp WAV existed at spawn and is gone after; failing script ⇒ `{ok:false, error}`; in-flight guard: second concurrent call refused.
- `voice:status` branches: missing binary ⇒ `{binary:false}`; fake binary + no model ⇒ `{model:false}`; pre-seeded model file ⇒ `{model:true}` and **no fetch attempted** (the only download coverage — live fetch/stream/rename is testing Node, skipped by TD ruling).
- `views.test.tsx`: `MicButton` SSR case; all four host views still render.
- Regression: full `npm test` / `lint` / `build` green.

## Out of scope

Non-English models or model-choice UI (ADR revisit). Streaming/partial transcription. Push-to-talk hotkeys. Bundling binary or model in installers. Windows/Linux voice. Download resume (failed download restarts). AudioWorklet migration. Cursor-position insertion.
