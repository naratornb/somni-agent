# M13 — Work-item model v2 + the Board — Execution Brief

## Context

Phase 3 pivots somni's core to a Jira-vocabulary kanban SDLC fused with Matt Pocock's engineering workflow (grilled specs gate execution). Decided in the 2026-08-27 planning session; governing design: architecture.md §4.1 (v2 item schema) and §9 Phase 3. M13 is the clean break: the `.somni/` work-item store v2 replaces Workflows/Queue/ticks, and a kanban Board replaces WorkflowsView as home. Grooming (M14), capture/palette (M15), and skills/implement-discipline (M16) build on it — this milestone ships with hand-authored stories.

## Goal & success criteria

In a fresh scratch repo:

1. Create a story on the Board; moving it to Ready is **refused** (main-process enforcement) until it has a non-empty spec body and ≥1 subtask.
2. Add a Ready story to the pipeline → drain runs its subtasks sequentially in a worktree → card lands in **Review** with a report. A deliberately failing story lands in **Needs Attention**.
3. Kill the app mid-run → relaunch offers Resume (existing machinery, now keyed by story).
4. Old `runs/` from a v1 repo still render in Runs view; v1 `workflows/` are ignored without error.
5. `npm test` and `npm run build` green.

## Scope

### Engineer

Dependency order — store/engine lands and passes tests **before** the Board UI starts:

1. **Store v2** (`src/main/store.ts`): flat item store per architecture.md §4.1 — `items/SOM-<n>-<slug>.md` (frontmatter: `id`, `kind: idea|epic|story`, `status: backlog|grooming|ready|in-progress|needs-attention|review|done`, `epic?`, `blockedBy?`, `created`; body = spec) + `items/….tasks.json` sidecar (stories; the existing task array shape verbatim) + `seq` counter (`SOM-` prefix fixed, single sequence, never reused) + `backlog.json` repurposed as Backlog-column ordering. Extend the existing hand-rolled frontmatter parser — no YAML dependency. Loader ignores v1 `workflows/`; `runs/` format untouched (`run.json`'s `workflow` key name is frozen; it now carries a story id).
2. **Ready gate in main**: `item:setStatus` and `pipeline:add` IPC both refuse `ready`/pipeline entry unless spec body non-empty AND sidecar has ≥1 selected subtask. Main is the authority; UI merely hides affordances.
3. **Executor** (`src/main/executor.ts`): the tick dies — status is the tick. `pipeline:add` sets `in-progress` + `wakeDrain()`. `next()` scans items with `status: in-progress` not in `activeSlugs` and all `blockedBy` items `done`. Completion writes the transition: Completed → `review`, Failed → `needs-attention`, Cancelled → `ready`. Worktree-per-run, retry, gate, resume, nightly/keep-running drains, report generation: reused untouched.
4. **IPC** (`src/main/repoIpc.ts`): item CRUD (create/read/update/delete, setStatus, backlog reorder), replacing workflow CRUD.
5. **Board UI** (after M13-ui.md is accepted): `BoardView.tsx` — seven columns (Backlog / Grooming / Ready / In Progress / Needs Attention / Review / Done), drag between columns (status change via IPC; refusals surface inline), Backlog ordered by `backlog.json`, Needs-Attention cards offer Re-run; `StoryPanel.tsx` — spec body + subtask editor, cannibalizing WorkflowsView's task-row/role-dropdown internals. Delete `WorkflowsView.tsx`; Board becomes home in `App.tsx` nav. Grooming column renders (empty affordance until M14). Review-card Accept → `done` (plain status change; report/branch tooling stays in RunsView).

Constraints: AGENTS.md architecture rules (business logic in main, plain files, no DB); CONTEXT.md v2 vocabulary is authoritative — code identifiers follow it (Item/Epic/Story/Subtask; engine names unchanged).

### Tester

- Store round-trip: frontmatter parse/serialize for every field incl. `blockedBy` lists; seq monotonicity; v1-repo coexistence (workflows/ ignored, old runs render).
- Gate: `item:setStatus`→ready and `pipeline:add` refusal paths (empty spec, zero subtasks, zero *selected* subtasks).
- Drain: blockedBy ordering (blocked story waits for blocker `done`), completion transitions (review / needs-attention / ready on cancel), resume after kill mid-run.
- End-to-end in a scratch repo per success criteria 1–4, with concrete failure output.
- Extend the existing vitest suites next to the modules they cover.

### Designer

Board home view + StoryPanel, as `design/briefs/M13-ui.md`: seven-column kanban within the existing "Nocturnal Mission Control" system (`design/stitch_somni_ai_orchestrator/DESIGN.md`, tokens in `src/renderer/src/assets/main.css`, atoms in `src/renderer/src/ui.ts`). Card anatomy (id, title, kind chip — muted "Idea" chip for ungroomed items, Story/Epic chips after grooming; status affordances: Groom →, Add to pipeline, Re-run, Accept), drag interactions incl. the refused-drop treatment for the Ready gate, column overflow behavior, empty states, StoryPanel layout (spec + subtask editor). PO/Engineer view modes both land on the Board.

- 2026-08-27 — Tester pass: 506 tests, no implementation bugs; added v1-run IPC coexistence, byte-level gate-refusal, and module-level end-to-end (idea → refusal → ready → drain → review / needs-attention) coverage.
