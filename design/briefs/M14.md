# M14 — Grooming — Execution Brief

## Context

Phase 3 milestone 2 (architecture.md §9 Phase 3). M13 shipped the item store, the hard Ready gate, and the Board; stories were hand-authored. M14 re-aims the M8 interview machinery (chat.ts + DraftView) into **Grooming**: the grill interview that turns intent into an approved Spec and tracer-bullet Stories with Subtasks and blocking edges — the only AI path to Ready. The Pocock discipline encoded: grill (relentless Interview) → spec → tickets.

## Goal & success criteria

1. Groom an existing Backlog item: `Groom →` opens the Grooming view, item status flips to `grooming` on the first turn, transcript keyed `chats/<id>.jsonl`. The Interview runs one `somni-question` at a time with Propose Now ever-present (M8 machinery, unchanged behavior).
2. Apply on an epic-shaped proposal converts the groomed item to `kind: epic` (keeping its id) and creates its Stories — each with Spec, `.tasks.json` sidecar, `epic: <id>`, resolved `blockedBy` — **all `ready`**; new Roles written only if their slug doesn't exist (existing role always wins, M8 rule). A story-shaped proposal converts the item to a single ready Story the same way.
3. Groom from scratch ("Groom" sidebar view, no item yet): `_draft` key as before; Apply creates the item(s) and renames the transcript to the root item's id.
4. Two generated stories with a blocking edge added to the pipeline drain in dependency order (M13 engine, exercised via groomed items).
5. A malformed `somni-groomed` block degrades to plain text exactly as M8 proposals did; nothing is written without Apply.
6. `npm test` and `npm run build` green.

## Staffing

Engineer + Tester. No Designer: the Grooming view is the existing interview surface (DraftView/DraftChatPanel/chatShared) restyled by pointer — no new interaction design.

## Scope

### Engineer

1. **`groomPreamble`** (chat.ts, successor of `draftPreamble`): keeps the Interview discipline (`somni-question` blocks, Propose Now) and the role-slug listing; adds the grooming charter — decide the altitude (big intent → Epic + tracer-bullet vertical-slice Stories with blocking edges; small intent → one Story); Specs state problem, approach, and verifiable success criteria; Subtask prompts are goals, not diffs (existing rule); when proposing, end with one fenced ```` ```somni-groomed ```` block:
   `{kind: 'epic'|'story', name, spec, stories?: [{name, spec, subtasks: [{title, prompt, role}], blockedBy?: number[]}], subtasks?: [...], roles?: [...]}`
   — `stories` for epics, top-level `subtasks` for a single story; `blockedBy` entries are **zero-based indices of earlier entries in the same `stories` array** (Apply resolves them to real ids; a forward/self/out-of-range index rejects the whole proposal — M8's invalid-role precedent). `roles` shape unchanged from M8.
2. **Parser + `applyProposal` v2** (chat.ts): parse/validate `somni-groomed` beside the existing fence helpers; Apply converts the groomed item in place (id kept; idea → epic|story; existing story re-groomed gets spec/subtasks rewritten) and creates child stories via the store's `nextId`/`saveItem`; everything lands `ready` (the epic itself lands `backlog` — it never executes); transcript `_draft.jsonl` renamed to `<rootId>.jsonl` for from-scratch grooms. Retire `loadWorkflows`/`saveWorkflow`/`deleteWorkflow` and the `somni-workflow` proposal path — nothing else uses them after this.
3. **Chat keying & guard**: sessions keyed by item id (or `_draft`); `isRunning(id)` refusal unchanged; first turn on an item sets `status: grooming` (a from-scratch groom creates nothing until Apply — M8 rule).
4. **Grooming view** (rename DraftView → GroomView, restore its nav entry as "Groom", add to `PO_VIEWS`): seeded from an item (`Groom →` passes id; turn-1 context = the item's name + spec body, replacing M8's stored-Brief prepend) or blank for from-scratch; Apply lands back on the Board. Board wiring: `Groom →` and Grooming-column card clicks open GroomView (StoryPanel stays the hand-edit surface from every other column); Needs-Attention cards gain **Re-groom** beside Re-run (opens GroomView, sets `grooming`).
5. Rename remaining `draft`-flavored identifiers the change touches (CONTEXT.md vocabulary); leave unrelated surfaces alone.

Constraints: chat machinery (streaming, resume, question cards, Propose Now, apply-is-the-only-mutation) is **reused, not rebuilt** — the diff should be preamble, proposal schema, Apply target, view rename, and wiring. AGENTS.md architecture rules apply.

### Tester

- Preamble: contains the somni-groomed schema, index-based blockedBy instruction, and role listing; turn-1 seeding for item-keyed grooms.
- Parser/validation: valid epic and story shapes; malformed JSON degrades to text; forward/self/out-of-range blockedBy index rejects; invalid role rejects (M8 parity).
- Apply: epic conversion keeps id and lands `backlog`; children get sequential ids, `epic` field, sidecars, resolved blockedBy ids, all `ready`; re-groom of an existing story rewrites in place; no disk writes before Apply; transcript rename on `_draft` groom; existing-role slug never overwritten.
- Guard: grooming refused for an executing story id.
- End-to-end (module level, M13 harness pattern): idea → simulated groomed proposal → Apply → blocked pair → pipeline:add → drain runs in dependency order → review.
- SSR render: GroomView in the views matrix; Board's Grooming-column click wiring; Re-groom affordance present.

## Out of scope

- Epic auto-completion when all children are done (manual drag for now).
- Re-grooming mid-pipeline (the guard refuses executing stories; that's enough).
- Voice/Refine changes — MicButton and RefineControl ride along untouched.
