# M15 — Capture + command palette — Execution Brief

## Context

Phase 3 milestone 3 (architecture.md §9 Phase 3). The Board (M13) and Grooming (M14) exist; what's missing is the PO's friction-free intake: "spill out ideas before I forget them." The capture design was produced and accepted during the Phase 3 planning session (recorded below — it is the UI contract; no Designer is spawned). Both surfaces land in this one milestone by explicit user decision: the capture modal *and* the Cmd+K palette.

## Goal & success criteria

1. Header "+" (every view, disabled with no repo) or **Cmd+N** opens the capture modal: prose textarea + MicButton. **Enter saves and keeps the modal open with a cleared, refocused field** — three Enters produce three "Idea" cards atop the Backlog column in order; Esc/backdrop closes without confirmation.
2. **Groom now →** in the modal saves the idea and lands in GroomView seeded with it (M14's item-keyed path).
3. The **inline quick-add row** pinned atop the Backlog column ("+ Add idea…", expands on focus, Enter submits and refocuses, collapses on blur-if-empty) produces identical items through the identical write path.
4. **Cmd+K** opens the palette: type free text → "Capture as idea" creates it; "Search" matches items by id/title and Enter opens that item (StoryPanel); navigation commands switch views (respecting PO mode); "Run pipeline" starts/joins the manual drain. Up/down + Enter + Esc keyboard flow.
5. **Backlog drag-to-reorder**: dragging a card within the Backlog column reorders it; the order persists via `backlog:set` (deferred here from M13 by TD ruling).
6. No OS-level global shortcut exists (explicitly deferred; later via Settings).
7. `npm test` and `npm run build` green.

## Accepted capture design (planning-session consult — the UI contract)

- One shared **CaptureModal** (chatShared.tsx component pattern): overlay + centered panel (existing surface/border/radius tokens, max-w ~480px), "New idea" heading, 4-row prose textarea (autoFocus, `TEXTAREA` but body font — prose, not code), `MicButton` reused as-is, buttons **[Groom now →]** (`BTN_GHOST`) and **[Add to Backlog]** (`BTN_PRIMARY`). Enter (and Cmd+Enter) = Add to Backlog. No toast — the modal staying open with a cleared field (or the card appearing) is the confirmation, consistent with the app's silent saves.
- **Backlog is the inbox** — no separate Inbox column, no new card type: captures are ordinary items (`kind: idea`, `status: backlog`), wearing the existing muted "Idea" `KIND_CHIP` until grooming shapes them.
- Capture always targets the currently loaded repo; no repo → header "+" disabled.
- The palette is the app's *second* surface for the same actions, not a second write path.

## Staffing

Engineer + Tester. No Designer (accepted design above; palette follows the same modal/overlay idiom).

## Scope

### Engineer

1. **Write path — no new IPC**: capture = the existing `item:save` create path (M13 already appends backlog-status creates to `backlog.json`). Renderer builds `{kind: 'idea', status: 'backlog', name: <first line>, spec: <remaining lines>}` — nothing typed is lost.
2. **CaptureModal** (new, beside the chatShared atoms): behavior per the accepted design; "Groom now →" saves then routes through App's existing groom handoff with the new id.
3. **App.tsx wiring**: header "+" button (`add` glyph — already subsetted) visible in every view; `keydown` listeners (mount effect, same pattern as existing IPC wiring) for Cmd+N (capture) and Cmd+K (palette) — skipped while a text field has focus for Cmd+N? No: both fire regardless (modals guard themselves); Esc closes top-most overlay only.
4. **Inline quick-add row** pinned atop the Backlog column in BoardView: ghost input "+ Add idea…" expanding on focus to textarea + MicButton, Enter submits + refocuses, collapses on blur-if-empty. Same renderer-side item construction as the modal (share the helper).
5. **CommandPalette** (new): overlay + input + result list. Commands: *Capture as idea* (uses current query text), *Search* (case-insensitive match over item id + name; Enter opens StoryPanel for it), *Go to <view>* (the nav list, PO-mode filtered), *Run pipeline* (the manual-drain action PipelineView's button uses). Ranking: exact/command matches first, then item hits; up/down/Enter/Esc.
6. **Backlog reorder**: HTML5 drag within the Backlog column computes the new order and calls `backlog:set`; cross-column drags keep M13 semantics untouched.
7. §8 of architecture.md already names these surfaces; touch docs only if behavior diverges.

Constraints: renderer holds no business logic (construction of an item literal is presentation, id allocation stays in main); no new dependencies; AGENTS.md rules.

### Tester

- Modal: Enter ×3 → three ordered Backlog items with correct name/spec split (multi-line capture), field cleared, modal open; Esc discards silently; Groom-now routes with the new id; no-repo disables header "+".
- Quick-add: same write results as the modal (shared helper — assert both produce identical items); collapse/expand behavior in SSR as far as the harness allows.
- Palette: capture-from-query; search hits by id and by title fragment; navigation respects PO mode; Run pipeline invokes the drain path; keyboard selection order deterministic.
- Reorder: `backlog:set` called with the correct new order on an intra-column drop; cross-column drop still routes `item:setStatus`.
- Regression: full suite; M13 gate/drain + M14 groom areas untouched.
- SSR: CaptureModal + CommandPalette in the views matrix; header "+" present in every view render.

## Out of scope

- OS-level global shortcut (later, via Settings); toasts; auto-grow textarea; a floating mini-window; palette fuzzy-ranking beyond substring match; skills/implement discipline (M16).
