# M16 — Vendored skills + the implement discipline — Execution Brief

## Context

Phase 3's final milestone (architecture.md §9 Phase 3, §10 risks). The Board, Grooming, and capture exist; what's missing is the Pocock execution half: somni injecting his skills into target repos so the unattended implement stage actually runs the discipline (TDD, closing code-review), with a bounded fix loop and an honest green signal. Governing risk notes: "Green-detection is the fragile joint" and "Skills injection touches repos somni doesn't own" (§10).

## Goal & success criteria

1. Fresh target repo → a visible one-time offer ("Set up engineering skills for this repo?") → accept → `<repo>/.claude/skills/<11 skills>` + `.claude/skills/.somni-skills.json` `{version}` marker + `docs/agents/issue-tracker.md` (somni-authored, declaring `.somni/items/` as the local tracker) + `docs/adr/` created + `CONTEXT.md` stubbed **only if absent** — an existing CONTEXT.md is never touched; only manifest-listed skill dirs are ever written.
2. Bumping the bundled manifest version surfaces an Upgrade offer; accepting overwrites exactly the manifest-listed dirs.
3. Every subtask spawn's argv carries the discipline preamble (unit-provable): it names the story's spec file path and instructs working through the injected `implement` skill (TDD at the seams).
4. After a story's last subtask, an auto-appended **Review task** code-reviews the diff vs `baseSha`, runs the repo's tests, and ends with a fenced ```` ```somni-verdict ```` block `{"verdict": "green"|"red", "findings": "..."}`. Red → an appended "Address review findings" task (findings as the goal) + a fresh Review task; **at most 2 fix cycles**, then the run Fails → `needs-attention`. Green → `review` column.
5. With `checkCommand` set in `.somni/config.json`, its exit code in the worktree is the primary deterministic signal: a failing checkCommand is red regardless of verdict text; a passing checkCommand makes a missing/malformed verdict green. Without checkCommand, a missing/malformed verdict is red (conservative — "green" must never mean "the parser shrugged").
6. `npm test` and `npm run build` green.

## Scope

### Engineer

1. **Vendor the skills**: copy these 11 from `/Users/flook/.agents/skills/` into `resources/skills/<name>/` (committed): `grilling`, `grill-with-docs`, `domain-modeling`, `to-spec`, `to-tickets`, `implement`, `tdd`, `code-review`, `research`, `diagnosing-bugs`, `resolving-merge-conflicts`. Write `resources/skills/manifest.json`: `{version: 1, upstream: "mattpocock/skills", skills: {<name>: <skillFolderHash from /Users/flook/.agents/.skill-lock.json, or "local" for the few not in the lock>}}`. Add `extraResources` to `electron-builder.yml`; resolve at runtime via `process.resourcesPath` (packaged) / app path (dev) — skills cannot live in the asar.
2. **`src/main/skills.ts`** (new): `skillsStatus(repo)` → `{bundledVersion, repoVersion | null}`; `injectSkills(repo)` → copies manifest-listed dirs into `<repo>/.claude/skills/`, writes the marker, writes `docs/agents/issue-tracker.md` from a template const (id scheme SOM-n, `.somni/items/` layout, frontmatter status vocabulary, blockedBy convention — so `to-spec`/`to-tickets`/`implement` running *inside the target repo* read and write somni's items), `mkdir -p docs/adr/`, stubs `CONTEXT.md` only-if-absent. Never writes outside the manifest list + those three paths; never deletes user files. IPC `skills:status`/`skills:inject`.
3. **Offer surfaces**: a dismissible banner when a loaded repo has no marker (and an Upgrade variant when `bundledVersion > repoVersion`), plus a Settings row showing status with a Set up / Upgrade button. House banner idiom; silent otherwise.
4. **Discipline preamble** (executor): a fixed const prepended to every subtask prompt (alongside the existing role-preamble prepend, never replacing it): read the Spec at `.somni/items/<file>`, work through the `implement` skill's discipline (TDD at agreed seams), stay within the story's scope.
5. **The review loop** (executor, after the last subtask of a story run):
   - If `checkCommand` set: `execFile` it in the worktree (existing timeout idiom); capture pass/fail + output tail.
   - Auto-append a **Review task** (precedent: report.ts's auto-appended Report task): prompt = code-review the diff vs `state.baseSha`, run the tests, end with the `somni-verdict` fence. Parse via the existing `lastBlock` helper.
   - Red (checkCommand fail OR verdict red; missing/malformed verdict = red unless checkCommand passed) → append "Address review findings" (findings = verdict findings and/or checkCommand tail) + a fresh Review task. Cycle counter caps at 2 fix cycles; still red → run Failed (existing path → `needs-attention`).
   - Green → run Completed (existing path → `review`).
   - Report/run.json record the verdict + checkCommand result per cycle (visible in RunsView's existing report rendering; no new UI).
6. **`checkCommand`** joins `.somni/config.json` (repo-level only; no global default) and the Settings repo section.
7. Docs: architecture.md already describes all of this (§9 M16, §10) — touch only if behavior diverges.

Constraints: runner-agnostic plumbing stays runner-agnostic (the preamble is prompt text, not flags); no new dependencies; atomic writes; AGENTS.md rules. Antigravity cannot read `.claude/skills/` — that stays a documented limitation (§10), no enforcement code.

### Tester

- Injection: fresh repo full-set write incl. marker + tracker doc + adr dir + CONTEXT stub; existing CONTEXT.md byte-identical after inject; a user-authored `.claude/skills/custom/` untouched; re-inject idempotent; version bump → upgrade path overwrites only manifest dirs; status IPC truthful in all three states (none / current / stale).
- Preamble: argv-level assertion that a subtask prompt carries the discipline const + the story's spec path + the role preamble in the right order.
- Loop: forced-red story (stub runner emitting red verdicts) cycles exactly: Review → Fix+Review → Fix+Review → Failed → `needs-attention`; forced-green lands `review`; malformed verdict without checkCommand → red; malformed verdict with passing checkCommand → green; failing checkCommand with green verdict text → red; cycle tasks appear in run.json with attempts/costs like any task.
- Regression: full suite; M13–M15 areas untouched.
