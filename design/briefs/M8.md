# M8 — Brief-first drafting — Execution Brief

## Context

Phase 2 begins. M6's "Draft with AI" chat requires a saved workflow and interviews loosely; M8 turns drafting into the Product-Owner's least-effort path: describe an outcome, answer one clickable Question at a time, Apply, and tonight's work is queued. Governing docs: [architecture.md §7–§9](../architecture.md), [CONTEXT.md](../../CONTEXT.md) (Brief, Interview, Question, Propose Now, Proposal, Apply). All design decisions below were resolved with the user at kickoff.

## Goal & success criteria

- `npm test`, `npm run lint`, `npm run build` pass.
- In the running app: a **Draft** sidebar view starts an interview with no saved workflow; the assistant asks one `somni-question` at a time rendered as clickable options (recommended highlighted); a typed custom answer works at any point; **Propose Now** forces a proposal; the proposal preview shows tasks, the Brief, and any new Roles (clashing slugs marked "already exists — will reuse"); **Apply** writes `workflows/<slug>.json` (ticked), `workflows/<slug>.brief.md`, new roles only, and renames `chats/_draft.jsonl` → `chats/<slug>.jsonl`; the app lands in the created workflow's editor showing the Brief read-only/collapsible.
- The editor chat asks one question at a time too, and includes the stored Brief in its turn-1 context. Its Apply does **not** change the workflow's tick.
- Chat is refused only for a workflow currently executing; the draft chat works while an unrelated pipeline runs.
- A malformed `somni-question` block degrades to plain text in the transcript.

## Staffing

UI-involved tier: **Engineer + Tester + Designer**. Designer first (new view); Engineer starts main-process scope in parallel; renderer work follows the design.

## Scope

### Decisions (frozen)

1. **Draft state**: pre-Apply chat runs under reserved key `_draft` (`.somni/chats/_draft.jsonl`); one draft at a time; only the transcript touches disk before Apply. Apply renames the transcript to `chats/<slug>.jsonl`.
2. **Brief storage**: sidecar `workflows/<slug>.brief.md`, written on Apply, deleted with its workflow. Wire format unified: the `somni-workflow` JSON block gains `"brief": str`; Apply splits files.
3. **Question blocks**: fenced ` ```somni-question ` containing `{"question": str, "options": [str], "recommended": str}`. Click = send the option text immediately as a normal user turn. Custom answers via the always-active input. Parse failure → raw text.
4. **Propose Now**: always-visible button sending a fixed, transcript-visible user message: stop interviewing, propose from answers so far plus stated assumptions.
5. **New Roles**: proposal JSON gains `"roles": [{slug, name, preamble, runner?, model?, effort?}]`. On Apply, write only slugs that don't exist — an existing role always wins; preview marks clashes "already exists — will reuse".
6. **Auto-tick**: brief-first Apply creates the workflow with `selected: true`; editor-chat Apply preserves the current tick.
7. **Entry point**: dedicated **Draft** view in the sidebar; after Apply, hand off to the created workflow's editor. Editor chat remains, adopting the interview discipline.
8. **Brief in UI**: read-only, collapsed by default, expandable in the workflow editor. No in-app editing.
9. **Guard**: relax the `chat:send` block from pipeline-wide to per-workflow (refuse only a currently-executing workflow's chat; `_draft` never blocked).

### Engineer

Dependency order; key seams named per file:

1. **Preamble & parsing** (`src/main/chat.ts`): rewrite `draftPreamble` for the Interview discipline — one question at a time via `somni-question` blocks, relentless until branches are resolved, Propose Now honored, proposal schema now `{name, brief, tasks, roles?}`. Add `parseQuestion` beside `parseProposal` (same last-fence-wins approach); extend `ChatProposal`. Preamble is turn-1 only (resume carries context) — the contract must ride turn 1.
2. **Draft chat + editor-chat brief context** (`chat.ts`): accept the `_draft` key everywhere a slug is; on editor chats, prepend the stored Brief (if any) to turn-1 context.
3. **Store** (`src/main/store.ts`): `brief` sidecar load/save/delete tied to workflow lifecycle; expose brief on the loaded `Workflow` (whitelist seams at the type, `loadRepo`, `saveWorkflow`); transcript rename on Apply.
4. **Apply path**: applying a brief-first proposal creates workflow (ticked) + brief sidecar + new-roles-only + transcript rename, atomically per existing write conventions; editor Apply gains brief/roles handling but preserves tick. Keep Apply the only mutation path out of chat.
5. **IPC/guard** (`src/main/repoIpc.ts`, `src/preload/index.ts`): per-workflow running check; draft-chat channels; keep preload type copies in sync.
6. **Renderer**: implement the Designer's spec — Draft view, question cards, Propose Now, extended proposal preview (brief + role cards), post-Apply navigation, collapsible Brief in the editor, editor chat question cards.

Constraints: architecture rules in [AGENTS.md](../../AGENTS.md); chat spawns stay read-only (`readOnly: true`, never `--dangerously-skip-permissions`); no new dependencies; hand-rolled parsing like the existing fence/frontmatter code.

### Tester

Verify, with concrete failing output on miss:

- §7 security invariant still holds for all chat spawns (read-only args, no skip-permissions) — extend the existing argv assertions.
- `parseQuestion`: valid block, malformed JSON (degrades), last-block-wins, fences nested in strings.
- Proposal schema: `brief` + `roles` parsing, unknown-key tolerance, invalid role entries reject cleanly.
- Apply: files written exactly as Decision 5/6 says (existing role untouched — byte-compare), transcript renamed, tick semantics per surface.
- Guard: chat allowed during a pipeline for non-running workflows and `_draft`; refused for the running one.
- Crash-safety: draft transcript survives restart; abandoned draft ("New chat") cleanly resets.
- Harness: reuse the fake-binary PATH technique from `src/main/chat.test.ts`.

### Designer

Design (component structure, states, CSS tokens from `src/renderer/src/assets/main.css`):

- **Draft view**: sidebar entry, empty state ("describe what you want"), interview transcript with question cards (options as buttons, recommended highlighted, clicked answer shown as a user turn), Propose Now placement, streaming state, proposal preview (task cards + Brief + new-role cards incl. the "will reuse" clash state), Apply/Dismiss, post-Apply handoff.
- **Workflow editor**: collapsible read-only Brief; question cards in the existing chat panel.
- Reuse the existing task-card/chat patterns; list open questions for the TD, don't ask the user directly.
