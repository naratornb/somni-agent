# M9 — Backlog & drain — Execution Brief

## Context

The pipeline today runs a fixed set snapshotted at start (`runJobs`, executor.ts): nothing joins mid-run, nothing unticks, nothing is scheduled. M9 makes the pipeline a **drain** per the frozen domain model ([CONTEXT.md](../../CONTEXT.md): Queue, Backlog, Draining, Nightly Window, Keep Running): ticks are consumed as work is picked up, newly ticked/promoted workflows join mid-run, and two new entry points (Nightly Window, Keep Running) differ from manual draining only by stop rule. Governing docs: [architecture.md](../architecture.md) §3/§9. Design resolved with the user and a TD-reviewed plan at kickoff; all decisions below are frozen.

## Goal & success criteria

- `npm test`, `npm run lint`, `npm run build` pass; the pinned executor invariants (concurrency bound, cancel, pause-abort, backoff-during-pause, fail-soft) stay green.
- In the running app: tick two workflows → **Drain queue** → both run and untick; tick a third mid-drain → picked up without restarting; park a workflow to the **Backlog**, reorder it, **Promote** it → it ticks (and a live drain picks it up); **Keep Running** on with an empty Queue → drain idles, a new tick runs within ~2 s, toggle off → in-flight finishes, drain ends; **Nightly Window** armed for a minute ahead → fires, drains the Queue, then shows disarmed; rate-limit pause and the concurrency cap behave exactly as before.
- A renderer opened mid-drain shows the correct drain state immediately (`pipeline:state`).

## Scope

### Decisions (frozen)

1. **One drain mechanism, three entry points** — manual "Drain queue", Nightly Window, Keep Running — differing only by stop rule. Manual/nightly stop when the Queue is empty and nothing is in flight; Keep Running idles and keeps scanning until toggled off.
2. **Untick-at-pickup**: a workflow's tick is consumed (atomic write, before spawn) when the drain picks it up. Untick write failure → skip that slug for the remainder of the drain, log once, fail-soft. Re-tick of a *running* workflow stays on disk and runs again after the current run — never concurrently with itself.
3. **Per-workflow Run button = tick + join** (start a manual drain if none active). `pipeline:start(repo, slugs)` = tick named slugs, wake the drain, start one if idle; PipelineView's button sends `[]`.
4. **Backlog** = `.somni/backlog.json`, a bare ordered array of slugs; prune missing slugs on load (in memory; persisted on next save). Promote = remove from backlog + tick + wake. Queue order = alphabetical slug (ponytail comment naming the `tickedAt` upgrade path).
5. **Nightly Window**: global settings `nightlyTime?: "HH:MM"` + `nightlyArmed?: boolean` (time survives disarm; armed persists app restart, re-armed on `app.whenReady`). Fire = write disarm *first*, then drain `lastRepo` (join silently if a drain is live; no-op if `lastRepo` invalid).
6. **Keep Running**: module flag, never persisted; toggling on mid-drain upgrades the stop rule in place; toggle-off finishes in-flight work, picks up nothing more, leaves unconsumed ticks on disk. **Cancel clears Keep Running.**
7. **Resume stays fixed-set** over the new loop (unchanged signature/semantics); a resume never scans the Queue.
8. **Status is queryable**: `getDrainState(): {mode, status, resumeAt?}`; the `pipeline:status` push gains `mode` (`mode: null` on the final Idle distinguishes "drain over" from keep-running idling). Renderer `busy` derives from drain state; starting/joining no longer wipes `runs`/`logs` (finished runs stay on the board).
9. **powerSaveBlocker** driven by status pushes: held while Running/Paused, released on Idle — a keep-running drain doesn't pin the machine while idling (lid-close wake remains user-side, architecture §10).

### Engineer

Dependency order (design details in the Decisions above; match existing style, no new deps):

1. **store.ts**: `setSelected(repo, slug, selected)` — targeted read-patch-write of the workflow JSON (never via `saveWorkflow`, which would clobber `tasks` from a stale snapshot); `loadBacklog`/`saveBacklog`; `loadRepo` returns `backlog`; deterministic `.sort()` on workflow file listing; `Settings` gains the nightly fields.
2. **executor.ts**: replace `runJobs` (:160-199) with `drainLoop(next, maxConcurrency, events, opts, mode)` — single supervisor loop, `Set` of in-flight promises, refill up to concurrency from `next()`, `Promise.race([...running, sleepOrWake(pollMs)])`, stop rules from `stopping`/`keepRunning` flags; `pickNext` re-reads `loadRepo` per refill and unticks at pickup; `sleepOrWake` (pollMs default 2000, injectable) + exported `wakeDrain()`; `startDrain(repo, worktreeBase, maxConcurrency, events, opts, mode)`; re-base `resumePipeline` on the loop with a fixed-set `next`; `getDrainState()`, `setKeepRunning(on)`; `cancelPipeline` additionally clears keepRunning, sets stopping, wakes. Emit 'Running' only when a job actually launches (no Idle/Running flapping). `makeGate`/`execute`/`runWorkflow`/`activeSlugs` untouched. Pure `msUntil(hhmm, now)` helper here for testability.
3. **index.ts**: `pipeline:start` reinterpreted per Decision 3; `pipeline:state`; `pipeline:keepRunning`; nightly arm/fire timer (~25 lines: `armNightly` on ready + on settings change, `fireNightly` per Decision 5); replace `awake()` with the status-driven blocker wrapper (Decision 9).
4. **repoIpc.ts**: export `patchSettings`; `wireRepoIpc(onSettingsChanged?)` invoked by `settings:set`; `backlog:set`, `backlog:promote` (+ wake).
5. **preload/index.ts**: sync types (`DrainMode`, `DrainState`, Settings fields, `RepoData.backlog`, status payload `mode`); methods `pipelineState`, `setKeepRunning`, `setBacklog`, `promote`.
6. **Renderer** per the Designer's spec: Backlog section in WorkflowsView, Keep Running toggle + drain-mode display in PipelineView (button becomes "Drain queue"), nightly time+armed fields in SettingsView; App.tsx busy/wipe rewiring per Decision 8.

Per Karpathy guideline 4, non-trivial logic ships with minimal vitest coverage (the Tester extends): drain pickup/untick, stop rules, `msUntil`, backlog round-trip each need at least one check. Existing `executor.test.ts` fixtures gain a `tick(...slugs)` helper (fixture saves workflows selected; a scanning drain sees all ticks).

### Tester

Verify with concrete failing output on miss; reuse the fake-binary + temp-repo harness in `executor.test.ts` (`describe('runPipeline')` :424-568):

- Pinned invariants stay green after setup migration to `startDrain`: concurrency bound (:483), cancel (:436), pause-abort (:514), backoff-during-pause (:534), fail-soft (:560 — reframed: a ticked workflow whose tasks are all deselected fails soft while others complete).
- Untick-at-pickup: one drained tick → `selected:false` on disk, exactly one run dir.
- Mid-run pickup: concurrency 1, slow first workflow, tick a second mid-run (pollMs 20) → both complete in one drain.
- Keep Running: idle pickup (tick lands while idling → runs), toggle-off mid-task (exactly one run; other tick still on disk), `getDrainState().mode` transitions, cancel clears the flag.
- Stop rule 'empty': manual drain with empty Queue resolves immediately with `[]`.
- Untick failure fails soft (read-only workflows dir; restore in afterEach).
- Resume: existing resume tests unchanged and green (fixed-set over the new loop); a tick during a resume is not picked up.
- `msUntil`: before/after the time today, midnight wrap.
- store: `setSelected` preserves `tasks`/`brief` sidecar untouched; backlog round-trip + prune of missing slugs.
- Status: `pipeline:state` getter shape mid-run and after; push payloads carry `mode`.

### Designer

- **WorkflowsView**: Backlog section under the main list — ordered rows, up/down reorder, Promote, and a "To backlog" park action on workflow rows; how a backlogged workflow's row differs (no tick checkbox — parked work never runs by itself).
- **PipelineView**: "Run pipeline" becomes "Drain queue"; Keep Running toggle; drain-mode/status display including keep-running idle ("Draining — waiting for work") and paused states; Cancel unchanged.
- **SettingsView**: nightly time (`<input type="time">`) + armed toggle, with visible armed/disarmed state.
- List open questions for the TD; don't address the user.
